# A-Maze-ing 役割分担・工数計画

## 前提

- 二人とも Python は授業で書ける程度、作業時間は1人あたり1日3時間ほどと仮定する。
- 工数は「その作業に実際に手を動かす時間」で、テストを書く時間を含む。

## 分担の方針

**「迷路を作る側（`mazegen` パッケージ）」と「それを使う側（アプリ）」で縦に切る。**
課題の第VI章が求める「再利用可能なパッケージ」と「メインプログラム」の境界が、そのまま担当の境界になる。

| | Aさん：生成コア（`mazegen/`） | Bさん：アプリ（それ以外） |
|---|---|---|
| 主な担当 | `MazeGenerator` クラス | `a_maze_ing.py` 全体 |
| 中身 | 迷路データ構造、PERFECT=True と PERFECT=False の生成、「42」パターン、seed による再現性、最短経路ソルバー | 設定ファイルのパースと検証、出力ファイルの書き出し、ASCII 表示と対話メニュー、エラー処理全般 |
| 周辺作業 | `pyproject.toml`、wheel のビルド、パッケージの使い方ドキュメント | Makefile、lint の設定、デフォルトの `config.txt`、妥当性チェッカー、結合テスト |
| 共同 | README、LICENSE.md、お互いのコードのレビュー | |

ソルバーを A 側に入れているのは、パッケージの要件に「少なくとも1つの解へのアクセス方法」が含まれているため。

### ディレクトリ構成

```
a_maze_ing.py          # B
config.txt             # B
mazegen/               # A（パッケージ）
  __init__.py
  maze.py
  generator.py
  solver.py
app/                   # B
  config.py
  writer.py
  display.py
tests/
pyproject.toml         # A
Makefile               # B
README.md / LICENSE.md # 共同
```

### `Maze` のインターフェース（叩き台）

A と B の唯一の接点。Phase 0 で確定させる。

```python
gen = MazeGenerator(width, height, entry, exit, perfect, seed)
maze = gen.generate()
maze.width, maze.height
maze.has_wall(x, y, "N")   # もしくは maze.cell(x, y) -> int（4bit）
maze.pattern_cells         # 42 パターンのセル（表示で色分けするため）
maze.solve() -> str        # "EESSN..."
```

座標は `(x, y)` の順で、x が幅方向、y が高さ方向。

## Phase 1：並行作業

### Aさん：生成コア（`mazegen/`）

| ID | タスク | 完了条件 | 工数 |
|---|---|---|---|
| A1 | 迷路のデータ構造：4bit のグリッド、壁の追加と削除（隣のセルも同時に更新）、外周の壁、範囲判定、隣接セルの取得 | 壁を1枚変えると隣のセルも必ず整合する、というテストが通る | 4.5h |
| A2 | 「42」パターン：ビットマップを定義し中央に配置、全方向を壁で閉じたセルにする。サイズが足りなければ配置せずに通知する | 小さいサイズではパターンなしで、呼び出し側にそれが分かる | 3h |
| A3 | PERFECT=True の生成：DFS を**ループで**実装（再帰だと深さ上限に当たる）。パターンのセルは避ける。`random.Random(seed)` を使う | 同じ seed なら毎回同じ迷路になる。analyzer が「完全迷路」と判定する | 4h |
| A4 | 最短経路ソルバー（BFS）：`"NESW"` の文字列を返す | 解けない場合の扱いも決めてテスト済み | 2h |
| A5 | **PERFECT=False の生成**：完全迷路から壁を選んで取り除き、ループを作る。<br>・3x3 の開放エリアを作らない<br>・四隅と中央を通路にする<br>・独立したループを2つ以上作る<br>・行き止まりはほぼなくす | analyzer が「プレイ可能なボード」と判定する（B7 のチェッカーでも確認） | **12h**（8〜16h の幅あり） |
| A6 | パッケージ化：wheel をビルドし、`mazegen-1.0.0-...whl` をリポジトリ直下に置く | 新しい venv に `pip install` して import できる | 2h |
| A7 | パッケージの使い方ドキュメント（インスタンス化、引数の渡し方、構造と解へのアクセス） | README にそのまま載せられる状態 | 1.5h |

**小計：29h**

### Bさん：アプリ

| ID | タスク | 完了条件 | 工数 |
|---|---|---|---|
| B1 | 開発用のダミー `Maze`（固定の小さな迷路） | A の本物がなくても B2〜B6 を動かせる | 1h |
| B2 | 設定まわり：`ConfigError`、`MazeConfig`、パーサー（コメント、空白、重複キー、必須キーの欠落、型変換、範囲チェック） | 異常系を含めて10ケース以上のテストが通る | 5h |
| B3 | 出力ファイルの書き出し：16進数のグリッド → 空行 → 入口 → 出口 → 経路。すべての行を `\n` で終える | 課題の出力例と同じ形式。analyzer が読み込める | 2.5h |
| B4 | ASCII 表示：壁、入口、出口、経路の重ね表示、42 パターンの色分け（ANSI カラー） | 20x15 程度の迷路が崩れずに表示される | 5h |
| B5 | 対話メニュー：再生成（新しい seed）、経路の表示切替、壁の色の変更、終了 | 不正な入力や Ctrl-C、EOF でも落ちない | 3h |
| B6 | `a_maze_ing.py`：引数チェック、全体の流れ、例外を捕まえてメッセージを表示し終了コードを返す | どんな異常な設定でもトレースバックが出ない | 2h |
| B7 | 妥当性チェッカー：壁の整合性、3x3 の開放エリア、連結性、行き止まりの数、ループ数 | **A5 のデバッグに使える状態で先に渡す** | 4h |
| B8 | 結合テスト：いろいろな `config` ファイルと `maze_analyzer.py` を組み合わせて検証 | 両方のモードで analyzer が合格する | 3h |

**小計：27.5h**

## マイルストーン

1. **M1（2日目）**：`Maze` のスタブが main に入る。ここから B が本格的に作業を始める。
2. **M2（1週目の終わり）**：A3 と A4 が完成し、B がダミーを本物（完全迷路）に置き換える。同時に B7 のチェッカーを A に渡す。
3. **M3（2週目の終わり）**：A5 が完成し、両モードで analyzer に合格する。
4. **M4（3週目）**：wheel、README、LICENSE がそろって提出。

## リスクと対策

- **A5 が最大のリスク。** 16h を超えそうなら、B の手が空いた時点（M2 以降）で、B7 のチェッカーを使った制約検証の部分を B が引き取る。
- **ボーナスは M3 のあとに回す。**
  - 行き止まりゼロ（A）：+4〜6h
  - 複数のアルゴリズム（A）：1つにつき +3h
  - 生成アニメーション（B）：+4h

  A5 を最初から「行き止まりを全部つぶす」方針で作っておけば、1つめのボーナスはほぼ追加コストなしで取れる。
- **評価では「その場で簡単な修正」を求められることがある。** 担当外の部分も説明できるように、PR は必ず相手がレビューする。
